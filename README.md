# Staff Pulse

Русскоязычный dashboard организационной структуры: дерево подразделений и аналитическая таблица с суммами по поддереву, живые обновления по WebSocket и AI-поиск на естественном языке. Все четыре этапа завершены и отмечены тегами `step/1`…`step/4`. Реальный OpenAI проверен вручную.

## Установка
Node.js ≥24 (сервер запускает TypeScript со встроенным удалением типов), Yarn Classic 1.22.

```sh
yarn install --frozen-lockfile
```

## Запуск одной командой
```sh
yarn dev
```
Клиент: http://127.0.0.1:5173. API: http://127.0.0.1:3001/api/org-tree, живой поток: ws://127.0.0.1:3001/api/live. Ctrl+C завершает оба процесса. Vite проксирует `/api`, включая WebSocket. Раздельно: `yarn dev:client`, `yarn dev:server`.

## Проверки
```sh
yarn typecheck
yarn lint
yarn test
yarn build
yarn size
```
Сборка frontend находится в `dist`. `yarn start:server` запускает backend без watcher. После `yarn build` команда `yarn preview` показывает production frontend с прокси `/api` к отдельно запущенному backend. Preview предназначен для локальной проверки, production-статику отдаёт Nginx.

## Docker Compose
Нужен запущенный Docker Engine / Docker Desktop с Compose v2.

```sh
cp .env.example .env
# При необходимости настройте .env, затем:
docker compose up --build
```

Приложение: http://127.0.0.1:8080 (порт меняется через `WEB_PORT`). Два сервиса: frontend на Nginx и backend на Node 24. Backend доступен только внутри сети Compose; снаружи API и WebSocket доступны через Nginx. Nginx сжимает статику gzip (уровень 6), проксирует `/api` и Upgrade WebSocket. Остановка: `docker compose down`. Повторная сборка после изменения кода: `docker compose up --build`.

Локальный `.env` не копируется в Docker-образы, ключ передаётся только backend во время запуска. Нельзя использовать префикс `VITE_` для ключа.

## AI-поиск
В таблице выберите **AI-поиск**, введите, например, «Отделы с бюджетом до 5 млн рублей и эффективностью выше 80%», нажмите **Найти с AI**. При наборе текста API не вызывается. Под формой появятся фактически применённые условия; **Сбросить** удалит фильтр. Обычный поиск по названию по-прежнему работает с debounce 250 мс.

Для реального OpenAI задайте в локальном `.env`:

```dotenv
AI_PROVIDER=openai
AI_MODEL=gpt-4.1-mini-2025-04-14
AI_API_KEY=ваш_ключ_только_в_локальном_файле
AI_BASE_URL=https://api.openai.com/v1
AI_TIMEOUT_MS=12000
```

После изменения `.env` перезапустите `yarn dev` или выполните `docker compose up -d --force-recreate`. Ключ в чат и репозиторий не нужен. Без ключа всё приложение работает, а AI-форма явно переходит на обычный текстовый поиск.

Сервер отправляет только текст запроса, описание полей и JSON-схему, без дерева и его показателей. Используется [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), `store: false`. Выбрана [фиксированная версия GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini); модель и base URL меняются через окружение. SDK не требуется для одного REST-вызова: используется встроенный `fetch` Node.

Фильтр ограничен названием, уровнем и диапазонами численности, бюджета и эффективности. Условия соединяются **И**, границы бывают строгими и включёнными. Все числовые условия применяются к готовым агрегатам полного дерева. Эффективность `null` не проходит числовое условие. Нет произвольных выражений, `eval`, генерации кода, OR или рейтингов. Если запрос не выражается схемой, модель должна вернуть отказ от интерпретации, после чего используется текстовый поиск.

Запрос ограничен 500 символами / 4 КБ HTTP-тела. Таймаут провайдера по умолчанию 12 секунд (конфигурация до 30 с), клиентский — 35 с. Ответ проверяется Zod на сервере и клиенте, включая порядок границ. Отсутствие ключа, таймаут, ошибка, отказ и невалидный ответ дают текстовый fallback с уведомлением. Повторная отправка блокируется в UI; backend допускает один одновременный AI-запрос на экземпляр и возвращает `busy` остальным. Это ограничение демо без авторизации, не многопользовательская квота.

`AI_PROVIDER=openai-compatible` использует тот же Responses/JSON-schema контракт и допускает пустой ключ для локального сервера. Совместимость других провайдеров не проверена; Chat Completions и Anthropic Messages этим адаптером не поддерживаются.

## Размер production frontend
Метод: `yarn build && yarn size`. Скрипт рекурсивно находит **все** `.js` и `.css` в `dist`, сжимает каждый `node:zlib.gzipSync` с уровнем 6 (как Nginx), суммирует байты и завершает проверку ошибкой при превышении **200 000 байт**. Чанки не исключаются.

Измерено: `assets/index-C3-UN8A8.js` — **125 531 байт gzip (125,53 КБ)**; отдельных CSS-файлов нет, styled-components включён в JS. Итого **125 531 байт**, ниже лимита. HTML, favicon и скриншоты не входят в показатель JS+CSS. Vite показывает другую оценку gzip из-за собственных настроек сжатия.

## Что показывает интерфейс
Дерево: собственные численность и эффективность подразделения, без сумм по дочерним.

Таблица: столбцы «Подразделение», «Уровень», «Сотрудники», «Бюджет», «Эффективность» (полные определения — в подсказках заголовков). Суммы включают сам узел и всех потомков, средняя эффективность взвешена по численности. При нулевой численности поддерева выводится «—». Бюджет — в формате `12 345 678 руб.` Числа в дереве и в таблице форматируются одной функцией.

Сортировка: клик по заголовку сортирует по возрастанию, повторный клик по тому же столбцу — по убыванию, клик по другому столбцу снова начинает с возрастания; Enter с клавиатуры работает так же. Равные значения сохраняют порядок дерева, строки без эффективности всегда в конце. Фильтр по названию применяется через 250 мс после последнего ввода, не различает регистр и буквы е/ё.

Клавиатура в таблице: стрелки вверх и вниз переходят по строкам, Home и End — к первой и последней, Enter выделяет узел. В порядок обхода Tab попадает одна строка, как в гриде.

Связь панелей двусторонняя: выбор строки таблицы выделяет узел в дереве, раскрывает его предков и прокручивает дерево к нему; выбор узла в дереве прокручивает таблицу к его строке.

От 1280 px дерево и таблица показываются рядом, а рабочая область занимает ровно высоту окна: прокручиваются панели, а не страница. На меньшей ширине работает переключатель «Дерево / Таблица», а выбор строки возвращает к дереву. Если панель таблицы при этом скрывается, фокус переходит на выделенный узел дерева. В режиме рядом фокус остаётся в таблице.

## Живые обновления
Сервер шлёт патчи значений существующих узлов через WebSocket. Клиент применяет патч без повторного запроса снимка и пересчитывает суммы только у изменённого узла и его предков; строки вне этой цепочки сохраняют прежние объекты. В дереве подсвечиваются только собственные значения изменившегося узла, в таблице — суммы у него и у его предков; ячейки гаснут за 1.5 секунды, каждая по своему таймеру. При `prefers-reduced-motion` анимация отключается и подсветка просто держится это время.

В шапке индикатор соединения: «Подключаемся…», «В сети», «Нет связи, переподключаемся». При обрыве клиент переподключается с экспоненциальной задержкой от 500 мс до 10 секунд с джиттером; счётчик сбрасывается после успешного подключения.

Полный перезапрос снимка происходит только при разрыве согласованности: пропуск версии, чужая сессия после перезапуска сервера, неизвестный узел или отставание версии, о котором сообщил heartbeat. Обычные патчи HTTP-запросов не вызывают. Подробности контракта — в [модели данных](docs/data-model.md) и [ADR 004](docs/adr/004-live-updates.md).

## Конфигурация и ограничения
Настройки: `.env.example`. Для локального сервера `HOST` по умолчанию 127.0.0.1, `PORT` — 3001; Vite читает тот же PORT. В Compose backend слушает 0.0.0.0:3001 внутри контейнера, внешний порт задаёт `WEB_PORT`. `LIVE_INTERVAL_MS` — период патчей (2000), `LIVE_HEARTBEAT_MS` — heartbeat (5000); 0 отключает соответствующий таймер. Без обоих видов сообщений клиент переподключится по сторожу молчания через 12 секунд. Параметры AI приведены выше. Данные детерминированы, не сохраняются в БД. Четыре корня, 40 узлов, три уровня.

Живые изменения касаются только значений существующих узлов: добавление, удаление и перемещение не входят в объём, поэтому структура дерева живёт столько же, сколько снимок.

Агрегаты считаются один раз на снимок, а при патче пересчитываются только по цепочке предков; фильтр и сортировка работают поверх готовых строк.

Кэш свежий 5 секунд; патчи обновляют его вместе с готовыми агрегатами. Query retry выключен, доступна кнопка повтора. Восстановление пропущенного live-потока повторяется отдельно с задержкой 1–10 секунд до согласования версий. Если не удалась первая загрузка, вместо дерева показывается экран ошибки. Если не удалось обновление, остаётся последний проверенный снимок: дерево, раскрытие и выделение сохраняются, над ним появляется предупреждение с кнопкой «Повторить обновление». Отмена запроса ошибкой не считается. В development StrictMode может отменить первый запрос и запустить второй — это проверка React, не polling.
