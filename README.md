# Staff Pulse

Русскоязычный dashboard организационной структуры. **Этап 1 — FOUNDATION** принят (тег `step/1`). **Этап 2 — CORE** реализован и ожидает приёмки. Этапы 3–4 не начаты.

## Установка
Node.js ≥22.12 (проверяется на 24), Yarn Classic 1.22.

```sh
yarn install --frozen-lockfile
```

## Запуск одной командой
```sh
yarn dev
```
Клиент: http://127.0.0.1:5173. API: http://127.0.0.1:3001/api/org-tree. Ctrl+C завершает оба процесса. Vite проксирует `/api`; сервер слушает только loopback. Раздельно: `yarn dev:client`, `yarn dev:server`.

## Проверки
```sh
yarn typecheck
yarn lint
yarn test
yarn build
```
Сборка frontend находится в `dist`. Production-сервер и Docker относятся к этапу 4. `yarn preview` показывает статику, но не проксирует API: для проверки текущего этапа используйте `yarn dev`.

Ручная проверка: при открытии видны три уровня дерева; сверните отдел и дивизион, используйте «Раскрыть всё»/«Свернуть всё». В таблице отсортируйте столбец кликом и двойным кликом, отфильтруйте по названию, кликните строку — узел выделится в дереве, его предки раскроются, дерево прокрутится к нему. Проверьте Tab/Enter/Space и ширины 1440, 1024 и 390 px.

## Что показывает интерфейс
Дерево: собственные численность и эффективность подразделения, без сумм по дочерним.

Таблица: столбцы «Подразделение», «Уровень», «Всего сотрудников», «Бюджет суммарный», «Средняя эффективность». Суммы включают сам узел и всех потомков, средняя эффективность взвешена по численности. При нулевой численности поддерева выводится «—». Бюджет — в формате `12 345 678 руб.` Числа в дереве и в таблице форматируются одной функцией, разряды разделяются одинаково.

Сортировка: клик по заголовку сортирует по возрастанию, двойной клик — по убыванию, Enter с клавиатуры переключает направление. Равные значения сохраняют порядок дерева, строки без эффективности всегда в конце. Фильтр по названию применяется через 250 мс после последнего ввода, не различает регистр и буквы е/ё.

Связь панелей двусторонняя: выбор строки таблицы выделяет узел в дереве, раскрывает его предков и прокручивает дерево к нему; выбор узла в дереве прокручивает таблицу к его строке.

От 1280 px дерево и таблица показываются рядом и прокручиваются каждое в своей панели; на меньшей ширине работает переключатель «Дерево / Таблица», а выбор строки возвращает к дереву. Если панель таблицы при этом скрывается, фокус переходит на выделенный узел дерева, иначе клавиатурный пользователь потерял бы позицию. В режиме рядом фокус остаётся в таблице.

## Конфигурация и ограничения
API поддерживает `PORT` (по умолчанию 3001). При смене порта нужно согласовать target proxy в `vite.config.ts`. Полная env-конфигурация будет в BONUS. Данные детерминированы, не сохраняются в БД. Четыре корня, 40 узлов, три уровня. Live-обновления и AI-поиск ещё не реализованы. Live в этапе 3 будет менять только показатели существующих узлов; структурные изменения исключены.

Агрегаты считаются один раз на снимок данных и мемоизируются; фильтр и сортировка работают поверх готовых строк и не пересчитывают суммы.

Кэш свежий 5 секунд: это не период polling. По истечении срока запрос возможен при возвращении фокуса, восстановлении сети или новом mount. Автоматических повторов нет, доступна кнопка повтора. Если не удалась первая загрузка, вместо дерева показывается экран ошибки. Если не удалось фоновое обновление, остаётся последний проверенный снимок: дерево, раскрытие и выделение сохраняются, над ним появляется предупреждение с кнопкой «Повторить обновление». Отмена запроса ошибкой не считается. В development StrictMode может отменить первый запрос и запустить второй — это проверка React, не polling.
