# 005. AI как преобразователь текста в ограниченный фильтр

## Контекст
BONUS требует реального поиска на естественном языке и текстового fallback. Значения таблицы меняются через WebSocket, поэтому отдавать LLM задачу выбирать конкретные строки означало бы получать устаревший результат и передавать провайдеру всё дерево.

## Решение
Пользователь выбрал OpenAI. Backend вызывает Responses API со strict JSON Schema через встроенный fetch, модель задаётся окружением. По умолчанию используется фиксированная версия `gpt-4.1-mini-2025-04-14`. Для одного endpoint отдельный SDK не нужен.

Модель получает только запрос и семантику разрешённых полей. Она возвращает название, уровень и числовые границы; `null` означает отсутствие условия. Все условия — И. Границы имеют признак включения, чтобы «больше 80» не превратилось в «от 80». Невыразимые запросы возвращают `filter:null`.

JSON Schema генерируется из Zod-формы. Сервер и клиент дополнительно проверяют диапазоны и запрещают лишние поля. Интерпретация в UI формируется из проверенного фильтра, не из свободного объяснения модели. Фильтр применяется к уже готовым агрегатам и остаётся актуальным при live-патчах; полного пересчёта не вызывает.

Любая ошибка API даёт явный текстовый fallback. На клиенте один активный запрос с отменой при сбросе/смене режима/редактировании и размонтировании. На backend — один AI-запрос одновременно на экземпляр; таймаут, предел длины и тела. Ключ только в серверном окружении, `store:false`, запросы и ключи не логируются.

## Альтернативы
Регулярные выражения вместо LLM не выполняют требование настоящего AI. Свободные выражения или код модели опасны и сложны для проверки. Отправка дерева в модель увеличивает объём данных и связывает результат с моментом снимка. Обобщённый SDK нескольких провайдеров избыточен; `openai-compatible` означает только совместимость с тем же Responses-контрактом.

## Последствия
Модель может неверно понять даже валидный запрос — пользователь видит условия и может сбросить их. Не поддерживаются OR, ранжирование и неуказанные числом оценочные слова. HTTP-адаптер проверен с моками и одним реальным запросом OpenAI 17.09.2026 (уровень отдела, верхняя граница бюджета, строгая нижняя граница эффективности). Широкая оценка качества интерпретации не проводилась. Ограничение одного запроса на сервер подходит демо, но не заменяет пользовательские квоты в многопользовательском продукте.
