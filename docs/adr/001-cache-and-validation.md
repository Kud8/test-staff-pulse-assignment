# 001. Проверка графа до помещения в кэш

Статус: принято для FOUNDATION.

## Контекст
Схема отдельных объектов не обнаружит циклы и потерянных родителей. Ошибочный граф может сломать обход UI. Снимок должен иметь одного владельца и поддерживать отмену загрузки.

## Решение
Проверять Zod-схему и целостность всего графа в API-клиенте до возврата queryFn. Хранить только проверенные снимки в TanStack Query; UI-состояние не включать в кэш. Индексы строить отдельно, сохраняя исходную плоскую структуру.

## Альтернативы
Проверка внутри компонентов дублирует обработку ошибок. Самописный fetch-кэш требует реализации отмены, дедупликации и обновления. Отдельный глобальный store создаёт второй источник истины.

## Последствия
Линейная проверка каждого полученного снимка; controlled error вместо частичного дерева. Если не прошло обновление, в кэше и UI остаётся последний проверенный снимок. Равные снимки сохраняют ссылки через structural sharing. Для live-патчей потребуется отдельная проверка, не полный parse/обход снимка при каждом событии.
