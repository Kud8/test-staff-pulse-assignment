# 002. Агрегация один раз на снимок и хранение взвешенной суммы

Статус: принято для CORE.

## Контекст
Таблица показывает суммы по узлу и всем потомкам и среднюю эффективность, взвешенную по численности. Фильтр с задержкой 250 мс, сортировка и выделение меняются часто, а данные между ними те же. В POLISH придут точечные патчи значений, после которых нужно обновить только затронутый узел и его предков.

## Решение
Чистая функция `aggregateTree` обходит снимок один раз: итеративный pre-order собирает строки в порядке дерева с уровнем вложенности, обратный проход добавляет суммы потомков в предков. Для каждого узла хранятся `headcount`, `budget` и `weightedPerformance`; среднее выводится из них, а не усредняется по потомкам. Результат мемоизируется по ссылке снимка, фильтр и сортировка работают поверх готовых строк.

## Альтернативы
Считать суммы при отрисовке строки: повторный обход на каждый ввод в фильтре и на каждую сортировку. Рекурсивный обход: глубина приходит из недоверенных данных. Хранить только среднее: нельзя ни корректно собрать среднее предка, ни применить будущий патч без полного пересчёта. Отдельный стор с селекторами: второй источник истины рядом с кэшем запроса.

## Последствия
Пересчёт происходит только при новом снимке; это закреплено тестом на число вызовов при фильтре, сортировке, выборе строки и переключении вида. Нулевая численность поддерева даёт `null` и «—» вместо деления на ноль. В POLISH патч узла изменит суммы по цепочке предков без полного обхода. Суммы бюджета — числа с плавающей точкой: при значениях, близких к MAX_SAFE_INTEGER, возможна потеря точности; данные задания на порядки меньше.
