# 003. Сортировка таблицы: клик, двойной клик и клавиатура

Статус: принято для CORE.

## Контекст
Задание требует сортировку по любому столбцу, где двойной клик даёт обратный порядок. Двойного клика с клавиатуры не существует, поэтому у клавиатурного пользователя не должно остаться недоступного направления. Строки без эффективности (нулевая численность) нельзя сравнивать как числа.

## Решение
Одиночный клик (`event.detail === 1`) сортирует по возрастанию, `dblclick` — по убыванию, активация с клавиатуры (`event.detail === 0`) переключает направление. Клики с `detail ≥ 2` игнорируются, иначе третий клик подряд сбросил бы обратный порядок. Направление отражается в `aria-sort` заголовка и в стрелке. Сортировка устойчивая: равные значения сохраняют порядок дерева, пустая эффективность всегда в конце независимо от направления.

## Альтернативы
Переключение направления одним кликом противоречит формулировке задания. Отдельная кнопка направления добавляет шум в заголовок. Shift+клик скрыт от пользователя и не помогает клавиатуре.

## Последствия
При двойном клике браузер сначала применяет возрастание, затем убывание: таблица пересортировывается дважды, промежуточный кадр заметен только как мгновенная перестановка и на 40 строках не влияет на отзывчивость. Заголовок получает `user-select: none`, чтобы двойной клик не выделял текст, и `touch-action: manipulation`, чтобы на сенсорных экранах жест не уходил в double-tap-to-zoom; на реальном iOS Safari это не проверялось. Для строк без эффективности направление сортировки не меняет их положение, это описано в интерфейсе колонкой «—».
