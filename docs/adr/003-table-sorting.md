# 003. Сортировка таблицы: повторный клик и клавиатура

Статус: принято для CORE, уточнено на этапе POLISH.

## Контекст
Задание требует сортировку по любому столбцу, где повторное действие даёт обратный порядок. Сначала это было прочитано буквально как двойной клик мышью, но такое поведение неочевидно: пользователь кликает второй раз и получает не разворот, а повторную сортировку по возрастанию. Двойного клика с клавиатуры к тому же не существует, поэтому у клавиатурного пользователя не должно остаться недоступного направления. Строки без эффективности (нулевая численность) нельзя сравнивать как числа.

## Решение
Клик по заголовку сортирует по возрастанию; повторный клик по тому же столбцу разворачивает порядок; клик по другому столбцу снова начинает с возрастания. Мышь и клавиатура идут через один обработчик `onClick`, отдельного `onDoubleClick` и разбора `event.detail` больше нет. Направление отражается в `aria-sort` заголовка и в стрелке. Сортировка устойчивая: равные значения сохраняют порядок дерева, пустая эффективность всегда в конце независимо от направления.

## Альтернативы
Двойной клик для убывания (прежнее решение) требовал различать `event.detail`, не воспроизводился с клавиатуры и не угадывался пользователем. Третье состояние «без сортировки» в цикле не добавлено: исходный порядок — это порядок дерева, отдельного запроса на его возврат нет. Отдельная кнопка направления добавляет шум в заголовок, Shift+клик скрыт от пользователя.

## Последствия
Быстрый двойной клик мышью теперь обрабатывается как два переключения подряд: если столбец уже отсортирован по возрастанию, порядок развернётся и вернётся обратно. Заголовок сохраняет `user-select: none`, чтобы серия кликов не выделяла текст, и `touch-action: manipulation`, чтобы на сенсорных экранах жест не уходил в double-tap-to-zoom; на реальном iOS Safari это не проверялось. Для строк без эффективности направление сортировки не меняет их положение, это описано в интерфейсе колонкой «—».
