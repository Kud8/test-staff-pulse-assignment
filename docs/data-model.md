# Модель данных

GET /api/org-tree возвращает плоский массив `{id, name, parentId, headcount, budget, performance, updatedAt}`. id, name и parentId (кроме null) — непустые строки без пробелов по краям: такие значения отклоняются, а не нормализуются. parentId корня — null; допускается несколько корней. Пустой массив корректен.

headcount — неотрицательное безопасное целое; budget — конечное неотрицательное число в рублях до MAX_SAFE_INTEGER; performance — конечное число 0–100. Это **собственные**, а не суммарные показатели. updatedAt — ISO 8601 с Z или смещением часового пояса. Клиент также проверяет уникальность ID, существование родителей и отсутствие циклов за O(n).

Набор: 4 дивизиона × (1 дивизион + 3 отдела + 6 команд) = 40 узлов, 3 уровня. Имена, значения и дата воспроизводимы при перезапуске. Есть узел с нулевой численностью. Модель строит byId, children и roots; первые два уровня раскрыты.

## Агрегация — план этапа 2
Для узла хранить суммы headcount, budget и performance × headcount по узлу и всем потомкам. Средняя эффективность = weightedPerformanceSum / headcountSum; при headcountSum = 0 вернуть null, в UI «—». Не усреднять средние. Полный обход один раз на снимок; фильтр и сортировка выполняются после него и не меняют поддерево.

## WebSocket — план этапа 3, не действующий контракт
Предлагаемый патч: `{version, id, changes: {headcount?, budget?, performance?}, updatedAt}`. Версия снимка должна передаваться HTTP-заголовком, сохраняя плоский массив тела. Серверная сессия должна различаться после перезапуска. Протокол handshake/replay и тесты гонок будут определены при реализации POLISH.

Патчи содержат только значения существующих узлов. Добавление, удаление и перемещение исключены. Дубликаты игнорируются, пропуск версии требует replay либо явной однократной ресинхронизации. Обычные патчи не запускают GET. При изменении собственных показателей дельты сумм передаются только узлу и его предкам.
