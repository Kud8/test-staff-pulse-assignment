# Архитектура

## FOUNDATION
- `server/`: стандартный Node HTTP сервер, воспроизводимые данные в памяти. Без БД, авторизации и серверного фреймворка для одного endpoint.
- `shared/org.ts`: Zod схема и выведенный тип. Клиент проверяет недоверенный ответ, включая целостность графа.
- `src/api/org.ts`: HTTP, AbortSignal, контролируемые ошибки на русском: HTTP-статус, недоступный сервер, ответ не в JSON, некорректная структура. Отмена запроса пробрасывается как есть и не превращается в ошибку сети или формата.
- `src/api/query.ts`: единственный владелец server state — TanStack Query. staleTime 5000 мс, structural sharing сохраняет ссылки равных данных. Автоматический retry выключен: ошибка видна сразу, есть ручной повтор. По умолчанию устаревшие данные обновляются при mount/focus/reconnect; таймер polling отсутствует.
- `src/model/tree.ts`: чистое построение индексов дерева O(n), независимое от React.
- `src/ui/`: styled-components и вложенные семантические списки с disclosure-кнопками на всю строку. Нативные кнопки поддерживают Tab/Enter/Space. Не используется неполный ARIA tree widget.
- `App`: состояния запроса и мемоизация модели по ссылке снимка. Экран загрузки и полноэкранная ошибка показываются, только пока данных нет. Если не удалось обновление, над последним снимком выводится предупреждение с повтором; дерево не размонтируется. Выделение и раскрытие локальны для дерева.

Поток: GET → unknown JSON → Zod/проверка графа → Query cache → индексы дерева → UI. При удалении последнего подписчика Query отменяет потребляемый fetch signal. В StrictMode первый development запрос может быть отменён при проверочном размонтировании React.

## Следующие этапы (не реализованы)
CORE добавит независимый слой агрегации и таблицу; POLISH — версионированные патчи, обновление кэша и инкрементальных сумм; BONUS — production-развёртывание и серверный адаптер LLM. Глобальный state manager не требуется.
