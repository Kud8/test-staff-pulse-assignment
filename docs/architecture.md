# Архитектура

## Слои
- `server/app.ts`: фабрика сервера — HTTP и WebSocket на одном порту. GET отдаёт снимок и его координаты в заголовках, `/api/live` рассылает hello, патчи и heartbeat. Интервалы патчей и heartbeat настраиваются, в тестах отключаются.
- `server/live.ts`: чистая генерация патча (узел, поле, шаг) и применение патча к снимку сервера. Сервер проверяет собственный патч схемой узла прежде чем его разослать.
- `server/data.ts`: воспроизводимые данные в памяти. Без БД, авторизации и серверного фреймворка.
- `shared/org.ts`, `shared/live.ts`: Zod-схемы снимка и сообщений потока, общие для сервера и клиента. Клиент проверяет недоверенный ответ, включая целостность графа, и каждое сообщение сокета.
- `src/api/org.ts`: HTTP, AbortSignal, контролируемые ошибки на русском: HTTP-статус, недоступный сервер, ответ не в JSON, некорректная структура, отсутствие версии снимка. Отмена запроса пробрасывается как есть и не превращается в ошибку сети или формата.
- `src/api/query.ts`: единственный владелец server state — TanStack Query. В одной записи лежат плоские узлы, сессия, версия, индексы и агрегаты. staleTime 5000 мс. Равная или более старая HTTP-версия той же сессии сохраняет актуальную запись и её ссылки; полная агрегация выполняется только при принятии нового снимка. Query retry выключен: ошибка видна сразу, есть ручной повтор.
- `src/api/sync.ts`: применяет патчи атомарно в Query-кэш без полной агрегации. Один GET восстановления одновременно, включая присоединение к фоновому GET; до 256 патчей в буфере воспроизводятся поверх ответа. При ошибке или оставшемся разрыве — повтор с задержкой 1–10 секунд; dispose очищает таймер и запрещает поздние обработчики.
- `src/api/live.ts`: транспорт сокета. Разбирает и отбрасывает некорректные сообщения, следит за молчанием потока и переподключается с экспоненциальной задержкой, потолком и джиттером. См. [ADR 004](adr/004-live-updates.md).
- `src/model/tree.ts`: чистое построение индексов дерева O(n), независимое от React.
- `src/model/aggregate.ts`: чистая агрегация снимка за один обход без рекурсии. См. [ADR 002](adr/002-aggregation.md).
- `src/model/live.ts`: снимок как единое целое (версия, узлы, индексы, агрегаты) и применение патча: правила версий, пересчёт сумм по цепочке предков, список изменённых ячеек.
- `src/model/table.ts`: чистые фильтр и сортировка готовых строк. См. [ADR 003](adr/003-table-sorting.md).
- `src/ui/format.ts`: единственное место форматирования чисел, бюджета, эффективности и названия уровня — им пользуются и дерево, и таблица.
- `src/ui/useLiveOrg.ts`: связывает Query-кэш, сокет и синхронизацию. Локально хранит только статус соединения и подсветку, данные читает из кэша. Подсветка живёт 1.5 с и снимается по токену, таймеры гасятся при размонтировании.
- `src/ui/useTreeState.ts`, `src/ui/useDebouncedValue.ts`: раскрытие и выделение с запросом на показ узла; задержка значения фильтра.
- `src/ui/OrgTree.tsx`, `src/ui/AnalyticsTable.tsx`: styled-components. Дерево — вложенные семантические списки с disclosure-кнопками на всю строку; таблица — обычная `table` с `th scope`, `aria-sort`, кнопками в заголовках и клавиатурной навигацией по строкам с одной точкой входа в обход Tab. Обе панели показывают выделенный узел и подсвечивают изменённые ячейки.
- `src/ui/Dashboard.tsx`: раскладка и общее состояние дерева. От 1280 px обе панели показываются рядом, липнут под шапкой и прокручиваются внутри себя; ниже работает переключатель. Ширина строк дерева зависит от ширины панели, поэтому используются container queries.
- `App`: состояния запроса, индикатор соединения в шапке и выбор между состояниями и дашбордом.

Поток: GET → unknown JSON → Zod и проверка графа → координаты снимка из заголовков → Query cache → индексы дерева → агрегаты снимка → фильтр и сортировка → UI. Дальше снимок живёт от сокета: сообщение → Zod → правила версий → пересчёт узла и его предков → подсветка изменённых ячеек. Полный перезапрос происходит только при разрыве согласованности: пропуск версии, чужая сессия, неизвестный узел, отставание по heartbeat.

Агрегаты пересчитываются при новом снимке целиком, а при патче — только по цепочке предков. Фильтр, сортировка, выделение и раскрытие ветвей их не трогают.
